## [0.4.0] - 2026-11-13
### Changed — Story overhaul of all 8 routes (SPEC §32)
- Every route rewritten by an Opus author and then read through by a QA reader (≈ 280 continuity fixes): no cosmetic choices (false choices 43–69 % → 0 %), no forced chapter steps (6–10 per route → 0), every chapter step goes through a bridge node (where / when / who is present), every flag that is set is read later (21–49 never-read flags per route → 0), hard jumps explained or removed (18–48 → 0 unexplained).
- Nodes per route 89–111 → 103–140; typical run 52–62 nodes; random-play death rates stay within ±3 pts of v0.3.3 (aeldari −2 to −3); good-ending share in random play falls to 22–29 % because choices now have consequences.
- New engine features (§32.2–32.4): flag-conditional text (`alt`, `resultAlt`), event placement (`where`, `excludeFactions`), `bridge` / `jump` nodes, old saves fall back to the start of their chapter when a node was merged or removed (toast "Story updated").
- New endings (5, total 131): `tau_end_thirdwave`, `nec_end_ceasefire`, `nec_end_webway`, `mech_end_survivor`, `gsc_end_passenger`. Dark Mechanicum antagonist is now "Dark Magos Syrredin" (a "warsmith" is an Iron Warriors rank). Shared events and rumours re-placed so none fires where it contradicts the scene; Imperium route rumours 15 → 12.
### Added — Opening choice (SPEC §33)
- First new game asks "你熟悉战锤40K的设定吗？": 新人 keeps lore cards + clickable terms; 熟悉 turns both off (entries still collected in the codex). New setting "台词里的条目链接" (Settings). Returning players are not asked.
### Added — Cloud save (SPEC §34)
- Inside the claude.ai artifact, saves / codex / records / settings are mirrored to a private space on the viewer's account (db capability), so progress is no longer lost when the browser storage comes back empty. Restores on load, auto-pushes on every change; Settings → 云端存档 shows the state and has 立即同步. Outside an artifact nothing changes.
### Added — Dev tools
- `tools/dev/playthrough.js` (one seeded random run as readable text), `route_graph.js`, `route_converge.js`, `story_lib.js`, `event_matrix.js`, `validate.js --story-report / --story-gate / --gather-report`.
### Added — Ending illustrations (SPEC §31)
- All 131 endings have their own 192×108 pixel picture (≤ 32 colours, Bayer-dithered, original archetypes, no text or marks): 8 routes drawn by art agents with a shared kit (`tools/art/endkit.py`), strict gate `build_all.py --check-endings` (size, colours, near-empty, near-duplicate, luminance bands good > bad > death per route), deterministic re-render (byte-identical).
- UI (web): every ending screen shows its own picture. A fixed 16:9 box (pixel-crisp, 3 px frame in the ending's kind colour: gold good / grey bad / red death, `alt` = "结局插图：<title>" / "Ending illustration: <title>", async decoding, the space is reserved so nothing jumps while it loads) is the top of the ending panel: left of the title / cause / facts on landscape, full width above them on portrait. The dimmed old scene stays as the screen background. The panel now scrolls as a whole (picture, facts, "你认识了" recap) with the buttons pinned below it, so they are never covered at 1280×720, 1920×1080 or 390×844.
- 往生录 → 结局: unlocked tiles get a 16:9 thumbnail above the title; locked tiles show a flat dark box (no image, nothing spoiled) and "???" as before.
- `UI.endingArt(factionId, nodeId)` returns `end_<id>` when the manifest registers it, else the node's own scene. If the image is unregistered or fails to load, the node scene is shown instead (never a broken-image icon or the slime placeholder; if even that fails the box stays flat dark). No new setting.
- Validator: every ending node must have a manifest scene `end_<id>` and its PNG (error); a PNG that is not 192×108 is a warning (header read, no dependency); `--allow-missing-ending-art` turns the "missing" errors into ONE summary warning (for development while the art is being produced; the plain run is the release gate); `tools/dev/dump_endings.js --check` runs inside the validator (stale `tools/art/endings_brief.json` = warning, error if the ending count differs). `--sample` does not need ending art.

### Added — Track selection (SPEC §29b)

Switching back to auto crossfades (~1.5 s) to the remembered story mood. Unknown or malformed stored value → `auto`; included in the settings backup / import (§22); no save schema change.
- Track names (zh / en, grouped 安宁 Quiet · 不安 Uneasy · 交战 Combat · 终局 Endings · 势力 Factions): 标题 Title, 平静 Calm, 圣堂 Sanctum, 紧张 Tense, 亚空间 Warp, 战斗 Battle, 首领 Boss, 黎明 Dawn, 余烬 Ashes, 安魂 Requiem, 钛 T'au, 灵族 Aeldari, 死灵 Necrons, 兽人 Orks, 基因教派 Genestealer Cult, 机械神教 Mechanicus. The Settings list is a grouped two-column radio list with a ▶ preview per track (≈ 8 s, in the current style) and a muted "现在播放：<name>" line that follows the story in auto mode (and says 试听中 during a preview, 静音中 while muted).
- **♪ quick panel** next to the sound button (title screen, ending screen and the in-game toolbar): track select, music-style select, a ▶ preview for each, and the mute switch. Closes on outside press / Esc (focus returns to ♪) / language change; story hotkeys are ignored while it is open; works on mobile (full-width under the button). Both controls (panel + Settings) always show the same state. Muted ▶ says so instead of staying silent.
- API (`WH.Audio`): `getMoods()` → `[{id, group, zh, en}]`, `setTrack(id|"auto")`, `getTrack()`, `getPlayingMood()`, `previewMood(id)` (≈ 8 s from the top of that mood in the current style; stops itself, the running music resumes after; muted or unknown id → no-op), and `onChange(fn)` → unsubscribe (fires when what is playing changes; drives the "now playing" lines). `setMood()` while a track is fixed only remembers the story mood (returns `"fixed"`); `stop()` and `unlock()` behave the same for a fixed track. Works in every style; real files still override.
- The default output is unchanged: all 5 styles × 16 moods render identically to 0.3.3 within float noise (≤ 1e-4, the same as run-to-run noise).
- Tests: `audio_render.py` live block (fixed track survives `setMood` / death / warp in every style, crossfade to and from auto, unknown id → auto, every mood as a fixed track, `previewMood` timeline in every style, muted / unknown no-op, `stop()` cancels, fixed track before the first click starts on unlock); `audio_check.js` (API, names, groups); `smoke_test.py --only-track` (part of the default and `--real` runs: persistence, popover open / close / Esc / outside press, both controls in sync, mute, preview marks, zh + en, desktop + mobile layout, no `WH.Audio` → no track row). `audio_test.html` has a track dropdown + preview button.
### Changed — Rumours only in gathering places (SPEC §20c)
- Rumours (传闻) and past-life echoes (前世死讯) are heard **only on nodes that carry `gather: {zh, en}`** (mess hall, market, hab commons, queue …) — never mid-fight, in a warp storm or alone in a tomb. Endings, death nodes, nodes with `eventRoll` and every node without `gather` never roll.
- Engine: at a gather node every eligible unseen rumour is a candidate; the `when` score (§20b) is now only a preference (score 0 = idle chatter is allowed); the best score wins, ties random. Chance 0.7 (score ≥2) / 0.6 (score 1) / 0.45 (score 0); an echo gets 0.3 at a gather node where no rumour was heard (still ≤1 per run, chapter ≥2). Spacing (≥3 nodes) and cap (≤2 per chapter) unchanged; `rumorChance` / `echoChance` still override; own seeded streams, so rumours on/off never move the main RNG. `rumorMatches()` returns `[]` for non-gather nodes and includes score-0 candidates; `Rules.isGather(node)` exported.
- UI: a gather node shows a muted tag next to the chapter plate — "聚集区 · 食堂" / "Crowd · Mess hall" (desktop + mobile, follows the language switch, kept during the consequence beat); Settings → 传闻 has the hint "只会在聚集区听到 / Only heard in crowded places".
- Validator: `gather` shape (zh ≤ 8 chars, en ≤ 4 words), label contained in text.zh and text.en (error), forbidden on endings / death / eventRoll nodes (error), foe / warp / tomb scenes (warning), `alt.text` without the label (warning); per route with gather nodes: ≥ 8 nodes, ≥ 6 chapters, every origin ≥ 5 reachable and ≥ 5 passed on average in random play (errors; warning below 6), gather → gather hops (warning), rumours heard per run (target 3–6) and echo share in the report; a route without any gather node gets one warning "no gather nodes yet — rumours cannot fire". The old §20b "rumour unreachable / too generic" warnings are replaced by the §20c rule (no gather node in the rumour's chapter range); a rumour without `when` is now allowed (warning). New `node tools/dev/validate.js --gather-report [--faction f] [--runs N]` prints node / chapter / scene / label / reachable-by-origin per route.
- Sample data: two gather nodes — smp_004 (chapter 2 mess hall, cadia scores 2) and smp_002 (chapter 1 break area, nothing eligible); `smp_rum_never` moved to chapters 5–6.
- Tests: `smoke_test.py --only-gather` (part of the default and `--real` runs): tag on gather nodes only, no rumour / echo on a non-gather node even at chance 1 (300 random walks; every real route in `--real`), a rumour at a gather node with chance 1, natural chance ≈ 0.7, zh + en, desktop + mobile layout, Settings hint. Existing rumour / echo / rewind tests adapted to need a gather node.

## [0.3.3] — 2026-11-12
### Added — Rewind (SPEC §30)
- Setting 设置 → 允许回到上一个选择 / Allow going back one choice (`settings.rewind`, default **off**; title screen and in-game). When on: a "↶ 回到上一个选择" button next to 主页 and the hotkey **Z** (shown in the button tooltip and the settings hint). It restores the complete engine state from just before the last choice: stats, flags, taint, clock, visited nodes, rumour / echo state, pending-event state and all three RNG streams, so picking the same roll again gives the same result (no re-rolling a gamble); a different choice works normally. 30-deep in-memory stack, not saved (after a reload the button stays disabled until the next choice). Switch off = no button, no history, no snapshots (identical to 0.3.2; validator death rates unchanged).
- Knowledge is not rewound: codex entries (and lore cards already shown), rumours heard, chronicle, achievements and the Tzeentch collection stay unlocked. Play time keeps running.
- Endings and death: with the switch on, the ending screen has "↶ 回到最后一个选择". The ending reached stays recorded; the continued run writes a new record with `rewinds` (shown as ↶N in 往生录 and as a chip on the ending screen). Run records, slots and the autosave carry `rewinds` (additive; save schema stays 2, §22).
- Fairness: achievements that reward one clean run (`ach_fast`, `ach_survive_sanity`, `ach_taint_200`, `ach_resist_1`, `ach_resist_5`) only count runs with `rewinds == 0`; cumulative counters, origins, flags and codex progress are unaffected. Engine: `Game.canRewind()`, `Game.rewind()`, `Game.rewindCount`, `Game.setRewind(on)`, option `rewind: true`.
- Music style selector (SPEC §29, UI only): 设置 → 配乐风格 / Music style, radio cards with a ▶ 试听 / Preview button per style, applied at start-up and on change, saved as `settings.musicStyle` (default `chip`, unknown value → `chip`) and included in the settings backup. Reads `WH.Audio.getStyles() / setStyle(id) / previewStyle(id)` when `audio.js` provides them; until then it shows the single built-in 8-bit style.
- Tests: `smoke_test.py --only-v033` (rewind: identical state + roll after A → rewind → A, A → rewind → B, depth limit, ending rewind keeps the old record, switch off hides everything, save / load, achievements guard, desktop + mobile, zh + en; music style: cards, preview, persistence, export, start-up apply).

### Added — Music styles (SPEC §29)
- Four new original procedural music styles next to the default `chip` (unchanged, bit-identical output): `dark` 暗黑氛围 (detuned drones and pads, sparse metal and bells, sub-bass pulses only in combat), `organ` 哥特管风琴 (pipe-organ chords, vowel-like choir pad, slow arpeggios, timpani and gong in combat), `synth` 合成波 (saw bass arpeggios, gated pads, four-on-the-floor drums in combat) and `piano` 钢琴弦乐 (sparse piano motifs over slow string pads, driving string ostinatos in combat).
- Every style covers all 16 moods, keeps the per-node mood auto-pick and the 8 s hysteresis, and is arranged from the same song data as `chip` (same keys and tempo families), so a mood keeps its identity across styles. Loops are seamless; sections are all different (no verbatim repeat inside a loop). Each style is trimmed to the loudness of `chip` (RMS within 2 dB, peaks at or below -1 dBFS). SFX are shared.
- API (`WH.Audio`): `getStyles()` (id, names, descriptions in zh / en), `getStyle()`, `setStyle(id)` (crossfade about 1.5 s, unknown id → `chip`, idempotent), `previewStyle(id)` (about 8 s: a calm phrase, then a short tense one; stops itself; the running mood is silent meanwhile and resumes afterwards; `setMood` during a preview is deferred; `stop()` cancels it; muted → no-op), `styles` (map of style objects). The module does not persist the style (the UI saves `settings.musicStyle`). Real files in `assets/audio/files.js` still override procedural music in every style.
- Engine: new waves (organ, reed, flute, piano), per-note filter envelopes, a formant bank for the choir, drum voices (sub boom, gong, clap), 5-note chord voicings, voice caps and drop counters (`E.drops`).
- `tools/dev/audio_check.js` renders every style × mood offline in headless Chrome (Node only, no dependencies; `audio_dsp.js` holds the DSP) and checks NaN, peak, DC, loudness vs `chip`, loop seam, repetition before 40 s, silence and voice load; `--json` / `--from-json` to save and re-evaluate. `tools/dev/audio_render.py --styles` renders them and tests the live API (crossfade, preview timeline, deferred `setMood`, mute, fallback). `tools/dev/audio_test.html` has a style dropdown and one preview button per style.
- Not verified by ear: all four styles were checked by measurement only; they need a human listen (`tools/dev/audio_test.html`).

## [0.3.2] — 2026-11-12
### Added — Grudges (SPEC §28)
- Hurting a person has later costs, but only where that person is really present. A route declares `faction.npcs`; a harming choice sets `wronged_<npc>`; a later choice carries `grudge:{npc, p?, effects?, note}`; a node can add a presence sentence with `grudgeLine:{npc, text}`. While `wronged_<npc>` is set (and `forgiven_<npc>` is not) the choice shows a ⚠ tag and a small line saying why it is riskier, its roll chance drops by `p` (final clamp 5–95 %), the grudge's own penalties (hp / sanity / renown ≤ 0, corruption ≥ 0, small taint bumps) are added when it is taken, the consequence panel starts with the note, and the node text is followed by the italic `grudgeLine`. Nothing changes while the flag is absent or forgiven (same RNG draws, same results); saves need no new fields.
- Engine: `Game.choices()[i].grudge`, `Rules.rollChance(roll, stats, extra)`, `Rules.grudgeActive / grudgeOf / mergeEffects`, `Game.grudgeLine()`, `Game.nodeText()`, `Game.activeGrudgeNpcs()`, `step.grudge`, `step.consequence.grudge`.
- Validator: all §28 coherence rules (npc exists, `wronged_` set by a choice and reachable, presence by name in zh and en text / speaker or foe sprite / grudgeLine, harm named in the choice, never before the harm, bounds), field shapes and length limits, and a per-route report (wronged npcs, grudge choices, activations per run, death and claim rate with vs without grudges; warns above +3 pts death or ±1.5 pts claim).
- Content: all 8 routes (2–4 people each, 6–11 grudge choices per route, redemption choices where the story allows). Random-play death rate rises 0.3–1.9 points per route (limit 3); claim-ending rates unchanged. A few existing lines were softened where they contradicted a later scene (e.g. "never speaks to you again" → "for a long time").
- Tests: sample data has two npcs (`vik` present by speaker sprite, `mira` through a `grudgeLine`) and a redemption choice; `smoke_test.py --only-grudge [--real]`.
